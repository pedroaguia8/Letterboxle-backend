## Project overview

Go backend for Letterboxle, a daily Wordle-style movie-guessing game. Serves a JSON API consumed by a separate React frontend, backed by PostgreSQL. Live at letterboxle.pedroaguia8.dev.

## Commands

```bash
# Run
go build -o app && ./app                        # requires .env (see below) or env vars set
docker compose -f docker-compose.dev.yml up -d  # start local dev Postgres (app itself still runs natively, not in Docker)

# Test
go test ./... -cover              # full suite
go test ./internal/handlers/...   # single package
go test ./internal/handlers/... -run TestDbMovieOfTheDayToMovie   # single test

# Quality (all run in CI)
go fmt ./...
staticcheck ./...
gosec ./...

# Database
goose -dir sql/schema postgres "$DB_URL" up     # apply migrations
sqlc generate                                    # regenerate internal/database from sql/schema + sql/queries after editing either
```

Required env vars (`.env` in dev — copy `.env.example`, injected as secrets in CD): `DB_URL`, `TMDB_API_READ_ACCESS_TOKEN`, `PLATFORM`, `PORT`.

`docker-compose.yml` is prod-shaped (builds the app image, joins the external `npm` network) and is only ever run by `cd.yml` on the prod host — never run it locally, it'll fail (no `npm` network exists locally). `docker-compose.dev.yml` is unrelated to it (not an override/layer) and only provides a disposable local Postgres for development.

## Architecture

- **main.go** wires everything: loads env, opens the DB, starts the poster-fetching background worker, registers HTTP routes on `http.ServeMux`, and handles graceful shutdown on SIGINT/SIGTERM.
- **internal/database** is entirely generated by `sqlc` from `sql/schema/*.sql` (goose migrations) and `sql/queries/*.sql`. Never hand-edit files here — change the `.sql` sources and rerun `sqlc generate`.
- **internal/handlers** holds the HTTP layer (`ApiConfig` methods bound as handlers) and DTO mapping between generated DB row structs and the API's `Movie`/`movieDto` JSON shapes. `utils.go` has the shared `RespondWithJSON`/`RespondWithError` helpers all handlers funnel through.
- **internal/tmdb** is a small client for the TMDB API used to fetch movie poster URLs. `baseURL` is overridable via `SetBaseURL` for testing against a mock server.
- **internal/workers** runs `PosterFetcher`, a background goroutine started from `main.go` that fetches/caches poster URLs for today's and tomorrow's movie every 4 hours. Handlers also fetch a poster on-demand (`GetMovieOfTheDay`) if it's still missing when requested, so poster fetching happens in two places that share the same `PosterFetcher`/`tmdb.Client` logic.
- The `movie_of_the_day` table maps a date to a `movies.id`; there's currently no support for playing past days (`GetMovieOfTheDay` rejects any date param other than `"today"`).
- Movie search (`SearchMovies`) does fuzzy matching via Postgres `ILIKE` with `%`-joined search terms, capped at 20 results.

## CI/CD

- `ci.yml`: on PR/push to `main`, runs tests+gosec and separately fmt+staticcheck.
- `cd.yml`: on push to `main`, SSHes (via cloudflared tunnel) into the prod host, pulls, rewrites `.env` from secrets, rebuilds via `docker compose up -d --build`, then runs goose migrations inside the container.
